# 方案设计文档：支持短信 MFA 人工介入的 Playwright RPA Web 应用

## 1. 背景与目标

对需要 **MFA（多因素认证）** 的网站执行 RPA 自动化操作。本期先支持**短信验证码**场景。

核心难点：Playwright 自动化是一个长时间运行的异步流程，而短信验证码需要**人工实时输入**。因此系统必须能够"执行到一半暂停、等待用户输入、再从原地继续"。

目标：
- 提供自定义 Web 页面，一键启动对目标网站的 RPA。
- 当流程进行到短信验证时，页面出现输入框让用户输入验证码并提交。
- 验证码回传后，自动化流程继续执行后续指定操作。
- 新增目标网站尽量只写配置，不改代码。

## 2. 总体架构

```
用户浏览器(自定义页面)
      │  1. 点击开始 (HTTP POST)
      ▼
后端 API / WebSocket 服务
      │  2. 创建会话，启动任务
      ▼
任务编排器 (状态机 RpaSession)
      │  3. 驱动
      ▼
Playwright 浏览器实例 ──► 目标站点
      │  5. 到达 MFA，挂起
      ▼
      │  6. WS 推送 NEED_SMS_CODE
      ▼
用户浏览器(输入验证码)
      │  7. WS 回传 SMS_CODE
      ▼
任务编排器 (唤醒) ──► Playwright 填入并继续
```

## 3. 关键机制：暂停 / 恢复

用一个"可被外部 resolve 的 Promise"实现挂起等待：

- 自动化流程执行到 `waitSmsCode` 步骤时调用 `session.waitForSmsCode()`，返回一个 Promise 并 `await` 挂起。
- 该 Promise 的 `resolve` 函数被保存在会话对象里。
- 用户从前端提交验证码时，`session.submitSmsCode(code)` 调用 `resolve(code)`，唤醒挂起的 `await`，流程从原地继续。
- 设有超时（默认 3 分钟），超时则 `reject`，清理浏览器实例，避免资源泄漏。

## 4. 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | 原生 HTML + JS | 开始按钮 + 条件显示的验证码输入框 + 日志 |
| 实时通信 | WebSocket (`ws`) | 后端需主动推送"请输入验证码" |
| 后端 | Node.js + Express | 与 Playwright 同语言，异步天然契合 |
| 自动化 | Playwright (Chromium) | 非 headless 便于观察调试 |
| 会话状态 | 内存 Map | 生产可替换为 Redis |

## 5. 配置驱动的步骤解释器

每个目标站点一份配置（`siteConfigs.js`），定义 `url` + `steps` 数组。后端"步骤解释器"按序执行，遇到 `waitSmsCode` 触发暂停机制。新增站点只写配置。

支持的 action：

| action | 参数 | 说明 |
|---|---|---|
| `goto` | `url?` | 打开页面 |
| `fill` | `selector`, `valueRef`/`value` | 填入文本 |
| `click` | `selector` | 点击 |
| `waitForSelector` | `selector`, `timeout?` | 等待元素出现 |
| `waitForUrl` | `url`, `timeout?` | 等待 URL 匹配 |
| `waitSmsCode` | `timeout?`, `maxRetries?`, `errorSelector?`, `successSelector?` | ★ 挂起等验证码，支持错误重试 |
| `sleep` | `ms` | 固定等待 |
| `screenshot` | `path?` | 截图 |

## 6. 验证码错误重试机制

`waitSmsCode` 步骤内置重试循环：
1. 等待用户输入验证码 → 填入 → 提交。
2. 判定结果：
   - 若配置了 `successSelector` 且出现 → 成功。
   - 若配置了 `errorSelector` 且出现 → 判定验证码错误。
3. 错误时向前端推送 `SMS_CODE_INVALID`，重新弹出输入框，直到成功或达到 `maxRetries`。

## 7. 任务鉴权

- 启动任务的 API 需携带 `Authorization: Bearer <token>` 或约定的 API Key，校验通过才创建会话。
- WebSocket 连接需携带 `sessionId` + `token`，双重校验，防止会话被他人劫持。
- Token 通过环境变量 `API_TOKEN` 配置。

## 8. 安全与合规

- 登录凭据不落地前端存储；生产环境走 HTTPS / WSS。
- 每个任务独立 `browser.newContext()`，Cookie 隔离，支持并发。
- 会话超时与完成后自动回收浏览器实例。
- **合规**：确认对目标站点执行 RPA 已获授权。MFA 本用于阻止自动化，需具备合法权限。
